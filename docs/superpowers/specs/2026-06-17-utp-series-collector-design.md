# УТП по сериям — дизайн

**Дата:** 2026-06-17
**Репозиторий:** osatakti_mdv_b2b (JAC B2B scraper)
**Связанное:** [HANDOFF.md](../../../HANDOFF.md) (открытый пункт про УТП-блок),
[2026-06-16-jac-b2b-scraper-design.md](2026-06-16-jac-b2b-scraper-design.md)

## Проблема

Бот сейчас не формирует УТП. Он берёт с B2B-портала JAC сырые характеристики
(ТТХ) по каждой позиции и вываливает их, группируя на своё усмотрение. Это
спецификация, а не продающие преимущества — владельца качество не устраивает.

Цель: собрать с официальных сайтов производителей настоящие маркетинговые УТП и
сгруппировать их **по сериям**, чтобы бот отдавал готовые преимущества вместо
сырых ТТХ.

## Ключевые решения (согласовано с владельцем)

- **Гранулярность — серия.** Один набор УТП на всю серию, общий для всех
  типоразмеров. Все INTEGRA (07/09/12/18…) — одни УТП; вся MDV Aurora — свои;
  Mitsubishi Heavy Standard Inverter (07/09/12/18/24) — свои. Мощность не влияет.
- **Подход B: парсер-черновик + ручная вычитка.** Машина собирает ВСЕ
  УТП-кандидаты по сериям, владелец галочками оставляет важное (чтобы не раздувать
  текст), бот берёт уже вычитанный финал. Это повторяет прежний рабочий процесс
  владельца.
- **Связка JAC ↔ сайт вендора — по имени серии.** Поле `series`, которое скрапер
  уже тянет из JAC, по именованным настенным сериям совпадает с названиями серий
  на сайтах вендоров → ручная таблица «модель→серия» не нужна.

## Архитектура

Новый модуль `jac_scraper/utp.py` + подкоманды CLI. Логика та же, что у
существующего скрапера: «скрапер готовит файл, бот его читает». Сеть — как в
проекте: `session.trust_env=False`, в скриптах `NO_PROXY=*`.

Внутри — отдельный мини-экстрактор на каждый бренд (4 функции), т.к. сайты свёрстаны
по-разному. Общий каркас: обход страниц серий → извлечение УТП-пунктов текстом →
нормализация и сопоставление с серией JAC.

## Поток данных (3 шага)

1. **Сбор кандидатов** — `python -m jac_scraper utp-collect`
   - По каждому бренду обходит страницы серий, вытаскивает ВСЕ найденные
     УТП-пункты текстом.
   - Сопоставляет серию сайта с серией JAC (нормализация имени).
   - Выгружает `data/jac_utp_candidates.xlsx` и сырой бэкап
     `data/jac_utp_candidates.json`.
2. **Вычитка владельцем** — в Excel колонка «Брать»: любой непустой символ
   (напр. `x`) = взять этот УТП. Строки отсортированы по бренду→серии. Можно
   дописывать свои строки руками (нужно для серий с малым числом кандидатов).
3. **Сборка финала** — `python -m jac_scraper utp-build`
   - Читает отмеченный `jac_utp_candidates.xlsx`.
   - Пишет `data/jac_utp_latest.json` = `{бренд: {серия: [выбранные УТП]}}`.
   - Этот файл читает бот: по серии товара подставляет готовые УТП.

## Формат Excel-кандидатов

Колонки: `Бренд | Серия | № | Текст УТП | Брать`. Одна строка — один УТП-кандидат.
Колонка «Брать» пустая, заполняет владелец.

## Сопоставление серий

- Нормализация: верхний регистр, обрезка пробелов, схлопывание повторных пробелов.
- Прямой матч серии JAC ↔ серии сайта по нормализованному имени.
- Маленькая таблица синонимов (alias map) для расхождений написания.
- «Серии», которые на деле типы (настенный/канальный/кассетный/мульти), УТП по
  серии не получают — пропускаются, факт пишется в лог, чтобы пробел был виден.

## Охват и риски

- Охват: именованные настенные серии 4 брендов (основная масса позиций).
- Типы-категории (не модельные линейки) исключены из УТП по серии.
- **EUROKLIMAT — самый рискованный**: на сайте УТП по сериям почти не выложены
  текстом. По части серий кандидатов может быть мало или не быть вовсе → владелец
  дописывает руками в Excel. Формат это допускает.

## Обработка ошибок

- Недоступная страница серии или серия без найденных УТП → лог + пустой блок в
  кандидатах, чтобы пробел был виден владельцу (не молчаливое исчезновение).
- Сеть — через существующую сессию с `trust_env=False`.

## Тестирование

В стиле репозитория — офлайн, без сети:
- HTML-фикстуры по каждому бренду (сохранённые страницы серий) → проверка
  экстракторов.
- Юнит-тесты на нормализацию и сопоставление серий.
- Юнит-тест на сборку: отмеченный xlsx → корректный `jac_utp_latest.json`.

## Вне охвата (YAGNI)

- Автоматический cron-режим без вычитки (отвергнут — качество текста важнее).
- УТП на уровне отдельной модели/артикула.
- Изменения в боте — это отдельный репозиторий; здесь только производим файл
  `jac_utp_latest.json` и фиксируем его формат.
