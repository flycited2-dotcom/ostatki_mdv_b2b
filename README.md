# JAC B2B — сбор остатков и цен (b2b-jac.com)

Скрапер для B2B-портала поставщика JAC (на 1С-Битрикс), у которого пока нет API.
Логинится на портал, читает «бланк заказа» со складскими остатками и ценами,
выгружает в CSV / JSON / XLSX. Четвёртый поставщик в одном ряду с тремя
API-поставщиками.

## ⚡ Статус: РАБОТАЕТ

Логин (`flycited@gmail.com`) и пароль уже в `config/.env`. Парсер откалиброван под
реальную вёрстку портала. Проверено на живом сайте: **526 позиций** собрано.

```powershell
.\run_scrape.ps1            # собрать остатки/цены -> data\jac_stock_ГГГГММДД.{csv,json,xlsx}
.\run_scrape.ps1 check      # проверить вход
.\schedule_task.ps1         # поставить на ежедневный автозапуск
```

## Что собирается

Скрапер сам находит 4 верхнеуровневые категории бланка заказа и обходит их с
пагинацией (каждая категория агрегирует весь свой подраздел):

| Категория | ~Позиций |
|---|---|
| Бытовые сплит-системы | 223 |
| Мультисплит-системы | 163 |
| Полупромышленные системы | 125 |
| Аксессуары | 15 |

На каждую позицию: **модель** (артикул), **Ваша цена** (дилерская — именно она в
поле `price`, не РРЦ), **остаток** (колонка «Наличие», число + текст), категория,
а в `attributes` — **РРЦ**, **Холод, кВт** и остатки по складам **Крым** и
**Москва** (включая текстовые «Больше 50» / «Больше 100»).

> Технические нюансы портала (на будущее): корень `/orders/blank_zakaza/` товаров
> не отдаёт (только дерево категорий); если `SIZEN_1` не указывать явно в каждом
> запросе, страницы после ~10-й приходят пустыми (Битрикс берёт номер страницы из
> сессии) — поэтому в каждом URL явно `?PAGEN_1=N&SIZEN_1=10`; перелёт за
> последнюю страницу возвращает не пусто, поэтому число страниц берётся из
> пагинации, а не по «пустой странице».

## Авторизация (если сессия перестанет работать)

В `config/.env` основной способ — логин+пароль. Резерв — вставить `JAC_COOKIE`
(F12 → Application → Cookies → b2b-jac.com). Подбор логина не делается (Битрикс
блокирует аккаунт), браузерные cookie автоматически не вычитываются.

Подробности дизайна: [docs/superpowers/specs/2026-06-16-jac-b2b-scraper-design.md](docs/superpowers/specs/2026-06-16-jac-b2b-scraper-design.md)

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
copy config\.env.example config\.env   # затем впиши JAC_LOGIN
```

> Примечание: если pip ругается на SOCKS-прокси — выставь `$env:NO_PROXY="*"`
> перед установкой. Скрипты `run_scrape.ps1` делают это автоматически.

## Команды

| Команда | Что делает |
|---|---|
| `python -m jac_scraper check` | проверяет авторизацию и доступ к бланку |
| `python -m jac_scraper discover` | сохраняет HTML в `dumps\` и печатает карту таблиц/колонок |
| `python -m jac_scraper scrape` | собирает данные и пишет в `data\jac_stock_ГГГГММДД.{csv,json,xlsx}` |

Удобные обёртки: `run_scrape.ps1 [check|discover|scrape]` (UTF-8, логи в `logs\`).

## Автозапуск (ежедневно)

```powershell
.\schedule_task.ps1            # ежедневно в 07:30
.\schedule_task.ps1 -Time 06:00
```

## Формат вывода

Нормализованные поля на каждую позицию: `article` (артикул), `name`, `brand`,
`stock_qty` (число) / `stock_raw` (текст наличия: «много», «под заказ»), `price`,
`currency` (RUB), `unit`, `warehouse`, `source` (`jac_b2b`), `scraped_at` (UTC).

`json` — для слияния с тремя API-поставщиками в общий агрегатор. Точный маппинг
под их схему добавлю, когда дашь формат остальных трёх.

## Тесты

```powershell
.\.venv\Scripts\python -m pytest -q
```

Тесты офлайн (парсинг, нормализация чисел, экспорт, детект авторизации,
сквозной прогон через локальный мок-портал). Реальный портал в тестах не дёргается.

## Структура

```
jac_scraper/
  config.py     # чтение config/.env
  session.py    # авторизация (логин+пароль / cookie), детект «залогинен»
  catalog.py    # загрузка бланка/каталога + пагинация
  parse.py      # HTML -> Product (эвристики + калибровка)
  discover.py   # дамп HTML и карта структуры
  export.py     # CSV / JSON / XLSX
  models.py     # Product + нормализация чисел
  cli.py        # точка входа
tests/          # pytest + фикстуры + мок-портал
config/.env     # настройки (в .gitignore)
run_scrape.ps1  # обёртка запуска
schedule_task.ps1  # ежедневная задача планировщика
```
