# JAC B2B — сбор остатков и цен (b2b-jac.com)

Скрапер для B2B-портала поставщика JAC (на 1С-Битрикс), у которого пока нет API.
Логинится на портал, читает «бланк заказа» со складскими остатками и ценами,
выгружает в CSV / JSON / XLSX. Четвёртый поставщик в одном ряду с тремя
API-поставщиками.

## ⚡ TL;DR — что осталось сделать (1 шаг)

Весь код готов и протестирован. **Не хватает только логина** от портала
(пароль уже вписан). Сделай одно из двух в файле `config/.env`:

- **Вариант A (рекомендуется):** впиши `JAC_LOGIN=` — твой логин на b2b-jac.com
  (телефон / e-mail / код дилера; пароль `выдан владельцем` уже подставлен).
- **Вариант B (если логин не помнишь):** открой портал в браузере (ты там уже
  залогинен), скопируй cookie (`F12 → Application → Cookies → b2b-jac.com`,
  строку вида `PHPSESSID=...; ...`) и вставь в `JAC_COOKIE=`.

Потом:

```powershell
.\run_scrape.ps1 check       # проверить, что вход работает
.\run_scrape.ps1 discover    # сохранить реальный HTML и показать структуру
.\run_scrape.ps1             # собрать остатки/цены -> папка data\
```

Если на шаге `discover` колонки распознаны неверно — пришли мне отчёт/файл из
`dumps\`, я за пару минут откалибрую селекторы под реальную верстку.

## Почему так (контекст разработки)

Разработка велась без доступа к авторизованным страницам: был дан пароль, но не
логин, а подбор логина не делается (Битрикс блокирует аккаунт после серии
неудачных попыток). Скрытое чтение cookie из браузера тоже не делалось. Поэтому
парсер написан на устойчивых эвристиках и снабжён режимом `discover` для точной
калибровки под фактический HTML — это финальный 5-минутный шаг.

Подробности: [docs/superpowers/specs/2026-06-16-jac-b2b-scraper-design.md](docs/superpowers/specs/2026-06-16-jac-b2b-scraper-design.md)

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
copy config\.env.example config\.env   # затем впиши JAC_LOGIN
```

> Примечание: если pip ругается на SOCKS-прокси — выставь `$env:NO_PROXY="*"`
> перед установкой. Скрипты `run_scrape.ps1` делают это автоматически.

## Команды

| Команда | Что делает |
|---|---|
| `python -m jac_scraper check` | проверяет авторизацию и доступ к бланку |
| `python -m jac_scraper discover` | сохраняет HTML в `dumps\` и печатает карту таблиц/колонок |
| `python -m jac_scraper scrape` | собирает данные и пишет в `data\jac_stock_ГГГГММДД.{csv,json,xlsx}` |

Удобные обёртки: `run_scrape.ps1 [check|discover|scrape]` (UTF-8, логи в `logs\`).

## Автозапуск (ежедневно)

```powershell
.\schedule_task.ps1            # ежедневно в 07:30
.\schedule_task.ps1 -Time 06:00
```

## Формат вывода

Нормализованные поля на каждую позицию: `article` (артикул), `name`, `brand`,
`stock_qty` (число) / `stock_raw` (текст наличия: «много», «под заказ»), `price`,
`currency` (RUB), `unit`, `warehouse`, `source` (`jac_b2b`), `scraped_at` (UTC).

`json` — для слияния с тремя API-поставщиками в общий агрегатор. Точный маппинг
под их схему добавлю, когда дашь формат остальных трёх.

## Тесты

```powershell
.\.venv\Scripts\python -m pytest -q
```

Тесты офлайн (парсинг, нормализация чисел, экспорт, детект авторизации,
сквозной прогон через локальный мок-портал). Реальный портал в тестах не дёргается.

## Структура

```
jac_scraper/
  config.py     # чтение config/.env
  session.py    # авторизация (логин+пароль / cookie), детект «залогинен»
  catalog.py    # загрузка бланка/каталога + пагинация
  parse.py      # HTML -> Product (эвристики + калибровка)
  discover.py   # дамп HTML и карта структуры
  export.py     # CSV / JSON / XLSX
  models.py     # Product + нормализация чисел
  cli.py        # точка входа
tests/          # pytest + фикстуры + мок-портал
config/.env     # настройки (в .gitignore)
run_scrape.ps1  # обёртка запуска
schedule_task.ps1  # ежедневная задача планировщика
```
